# Accessibility that is checkable

Only keep rules an agent (or `scripts/audit.py`) can verify. Everything else is advice.

## Contrast

| Text | Minimum | Tool |
|---|---|---|
| Body text | 4.5:1 (AA) | `contrast.py` |
| Large text (>= 24px, or 18.66px bold) | 3:1 | `contrast.py` |
| UI borders and icons | 3:1 | `contrast.py` |
| Focus indicator vs adjacent colour | 3:1 | `contrast.py` |

```bash
python scripts/contrast.py "var(--color-ink)" "#ffffff"   # wrong: variables need resolved values
python scripts/contrast.py "oklch(0.24 0.02 260)" "#ffffff"
```

Pass a `--pairs` file for a whole palette:

```
oklch(0.24 0.02 260)  oklch(0.985 0.004 260)
oklch(0.55 0.2 262)   oklch(0.99 0 0)
```

## Focus

- Never `outline: none` (or Tailwind `outline-none`/`outline-hidden`) without a replacement.
- Focus must be visible on every interactive element, including icon buttons.
- `:focus-visible` with 2px offset is enough; the token is `--color-brand` or `--color-ink`.

## Names and labels

- Icon-only buttons need `aria-label` (and `title` for a tooltip).
- Inputs need a `<label for>` or `aria-label`; a placeholder is not a label.
- Images need `alt`; decorative images use `alt=""`.

## Keyboard

- Every action reachable by mouse is reachable by Tab + Enter/Space.
- Dialogs and popovers close on Escape, and return focus to the trigger.
- Do not trap focus outside modals.

## Motion and timing

- Respect `prefers-reduced-motion`.
- No autoplay that cannot be paused; no flashing above 3Hz.

## Content

- Errors say what happened and how to fix it, in the interface voice.
- Empty states invite the next action instead of apologising.
- Do not rely on colour alone to convey state; pair it with an icon or text.

## Audit

```bash
python scripts/audit.py src --tokens src/layout.css
```

Codes: `IMG_NO_ALT`, `ICON_BUTTON_LABEL`, `OUTLINE_NONE`, plus token hygiene
(`HARDCODED_COLOR`, `PX_FONT`). Exit 1 means fix before shipping.
